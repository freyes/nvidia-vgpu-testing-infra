# nvidia-vgpu-testing-infra

Terraform infrastructure for provisioning an OpenStack test bed on a single
libvirt host with NVIDIA vGPU passthrough, deployed and operated by Juju and
secured by Vault. The module stands up the libvirt network, storage pool,
volumes, and guest domains, then bootstraps a Juju controller and an
OpenStack control plane ready for vGPU-enabled instance testing.

## Prerequisites

- A bare-metal host with:
  - `libvirt` and `virt-install` installed and the `libvirtd` service running
  - IOMMU and VT-d enabled in the kernel command line
    (`intel_iommu=on iommu=pt`)
  - An NVIDIA GPU with vGPU support (e.g. A16, A30, A100) and the NVIDIA
    vGPU driver / `nvidia-vgpu-mgr` daemon running
  - Sufficient CPU, memory, and disk for the planned control-plane VMs
- `terraform` >= 1.7
- `juju` >= 3.x (for bootstrap and bundle deployment)
- `vault` CLI (for seal/unseal and secret authorisation)
- `libvirt` client tools (`virsh`, `virt-install`)

## Quick start

```
make init
make plan
make apply
```

Then follow the post-apply sections below: prepare the host, bootstrap Juju,
deploy OpenStack, and initialise Vault.

## Variables

The module is configured through variables in `terraform/variables.tf`.
The most common ones:

| Variable | Description | Default |
|---|---|---|
| `host_name` | Name of the libvirt host (used in resource naming) | `nvidia-vgpu-host` |
| `libvirt_uri` | libvirt connection URI | `qemu:///system` |
| `network_name` | Name of the libvirt bridge network | `vgpu-net` |
| `network_cidr` | CIDR of the management network | `192.168.100.0/24` |
| `pool_name` | Name of the libvirt storage pool | `vgpu-pool` |
| `pool_path` | Host path backing the storage pool | `/var/lib/libvirt/pools/vgpu-pool` |
| `control_plane_count` | Number of control-plane VMs | `3` |
| `control_plane_vcpu` | vCPUs per control-plane VM | `4` |
| `control_plane_memory` | Memory (MB) per control-plane VM | `8192` |
| `control_plane_disk` | Root disk size (GB) per control-plane VM | `80` |
| `vgpu_type` | NVIDIA vGPU type to assign to compute guests | `nvidia-223` |
| `image_source` | URL of the base cloud image for guests | _see variables.tf_ |

## Host and GPU preparation

1. Enable IOMMU on the host. Add `intel_iommu=on iommu=pt` (Intel) or
   `amd_iommu=on iommu=pt` (AMD) to the kernel command line and reboot.
2. Install the NVIDIA vGPU driver and start `nvidia-vgpu-mgr`.
3. Verify the GPU is visible and vGPU-capable:

   ```
   nvidia-smi
   mdevctl list
   ```

4. Run the host preparation script to install packages, configure libvirt,
   and seed the base cloud image into the storage pool:

   ```
   scripts/prepare-host.sh
   ```

## Juju bootstrap

After `make apply` the libvirt VMs are running. Bootstrap a Juju controller
against the libvirt cloud:

```
juju bootstrap libvirt-vgpu vgpu-controller
```

Then add the machines that Terraform provisioned and deploy the OpenStack
bundle generated by the module:

```
juju add-machine ssh:<ip-of-vm>
scripts/deploy-openstack.sh
```

`deploy-openstack.sh` runs `juju deploy` against the `bundle.yaml` rendered
by Terraform and waits for the model to reach `active`.

## OpenStack deployment

The OpenStack control plane is delivered through the Juju bundle rendered at
`bundle.yaml`. The bundle pins the OpenStack release and charm channels in
`terraform/variables.tf`; override them by editing the bundle template at
`terraform/templates/bundle.yaml.tpl` or by setting the corresponding
Terraform variables before `make apply`.

## Vault initialisation

Vault is deployed as a Juju application. Once the model is `active`,
unseal and authorise it:

```
scripts/vault-unseal-and-authorise.sh
```

The script initialises Vault, unseals it with the returned key shares, and
authorises the Juju applications that need secret access (Nova, Cinder,
Neutron). Keep the generated root token and unseal keys somewhere safe;
they are written to `vault-init.json` outside the repo by default.
